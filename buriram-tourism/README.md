# ศูนย์รวมข้อมูลท่องเที่ยวชุมชนจังหวัดบุรีรัมย์
### Buriram Community-Based Tourism (CBT) Portal

เว็บไซต์ศูนย์รวมข้อมูลการท่องเที่ยวโดยชุมชน (CBT) จังหวัดบุรีรัมย์ สัมผัสเสน่ห์วิถีถิ่นอีสานใต้ ดินแดนภูเขาไฟที่ดับสนิทแล้ว อารยธรรมขอมโบราณพันปี และภูมิปัญญาการทอผ้าไหมมัดหมี่ พัฒนาขึ้นตามมาตรฐานเว็บสมัยใหม่ ครบถ้วนทั้งด้าน Semantic HTML5, Responsive Design, JavaScript Functions, การเชื่อมต่อ Open-Meteo Public API, และการรองรับ SEO & Accessibility

---

## 1. โครงสร้างเว็บไซต์ (Website Structure)

เว็บไซต์ประกอบด้วย 3 หน้าหลักที่มีแถบนำทาง (Navbar) และส่วนท้าย (Footer) สอดคล้องกันอย่างสมบูรณ์:

- **หน้าแรก (`index.html`)**:
  - Hero Section ภาพรวมอัตลักษณ์ชุมชนและปุ่ม Call-to-Action
  - วิดเจ็ตสภาพอากาศปัจจุบันในบุรีรัมย์ เชื่อมต่อแบบเรียลไทม์กับ Open-Meteo API
  - สถิติชุมชนท่องเที่ยว (23 อำเภอ, 50+ ชุมชน, 12 รางวัลการันตี, 100% กระจายรายได้สู่ฐานราก)
  - 3 ชุมชนท่องเที่ยวไฮไลท์ (บ้านเจริญสุข, บ้านสนวนนอก, บ้านโคกเมือง)
  - 4 เสาหลักอัตลักษณ์ (ดินแดนภูเขาไฟ, อารยธรรมขอม, ไหมหางกระรอก, อาหารถิ่นพาแลง)
  - เสียงตอบรับจากนักท่องเที่ยวจริง (Testimonials)
- **หน้ารายการแหล่งท่องเที่ยว (`attractions.html`)**:
  - แดชบอร์ดรายงานสภาพอากาศบุรีรัมย์ฉบับเต็ม พร้อมพยากรณ์ล่วงหน้า 3 วัน และคำแนะนำท่องเที่ยวตามสภาพอากาศ
  - ช่องค้นหาข้อมูลแบบพิมพ์สด (Live Search with Clear Button)
  - แถบปุ่มกรองหมวดหมู่ (Category Filter Pills: วัฒนธรรม, หัตถกรรม, ประวัติศาสตร์, เกษตร)
  - ตัวเลือกเรียงลำดับข้อมูล (Sort by: ความนิยม, คะแนนรีวิว, จำนวนรีวิว, ตัวอักษร)
  - ตารางกริดการ์ดแหล่งท่องเที่ยวชุมชน 6 แห่ง พร้อมระบบแสดงผลกรณีค้นหาไม่พบ (Empty State)
  - หน้าต่างป๊อปอัปรายละเอียดเจาะลึก (Detail Modal) พร้อมกิจกรรมและเบอร์โทรติดต่อ
- **หน้าติดต่อเรา (`contact.html`)**:
  - การ์ดข้อมูลติดต่อศูนย์ประสานงาน (ที่อยู่สำนักงาน, สายด่วน, อีเมล, เวลาทำการ)
  - แบบฟอร์มติดต่อสอบถามและจองโปรแกรมศึกษาดูงาน พร้อมระบบตรวจสอบข้อมูล (Client-side Validation)
  - หน้าต่าง Modal สรุปข้อมูลที่ผู้ใช้ส่งเมื่อการตรวจสอบผ่านสมบูรณ์
  - ส่วนคำถามที่พบบ่อย (FAQ Accordion) ยุบ-ขยายคำตอบได้
  - แผนที่ตำแหน่งศูนย์ประสานงานบุรีรัมย์ (Responsive Google Maps Embed)

## 3. เหตุผลที่เลือกใช้เฟรมเวิร์คและไลบรารี (Frameworks & Libraries Rationale)

> โครงการนี้เลือกใช้ **Tailwind CSS (v3)** เป็นเฟรมเวิร์คหลักเนื่องจากมีความยืดหยุ่นสูงผ่าน Utility-first classes ช่วยให้จัดการ Responsive Breakpoints บนหน้าจออุปกรณ์ต่างๆ ได้อย่างแม่นยำ และรองรับระบบ Dark/Light mode ได้ทันทีโดยไม่ต้องเขียนโค้ด CSS ซ้ำซ้อน ขณะเดียวกันได้เลือกใช้ **Font Awesome 6** เป็นคลังไอคอนมาตรฐานสากลเพื่อสื่อสารสัญลักษณ์สภาพอากาศ ทิศทาง และการติดต่อได้อย่างชัดเจน เข้าใจง่าย และส่งเสริมประสบการณ์การใช้งานที่ดี (UI/UX)

## 4. ฟังก์ชัน JavaScript (เกินเกณฑ์ 3 ฟังก์ชัน)

| ลำดับ | ฟังก์ชัน | ไฟล์ | รายละเอียดการทำงาน |
| :--- | :--- | :--- | :--- |
| 1 | `toggleMobileMenu()` | `main.js` | ควบคุมการเปิด/ปิดเมนูนำทางบนหน้าจอมือถือและแท็บเล็ต พร้อมสลับไอคอน และตั้งค่า `aria-expanded` รองรับการกด Esc และคลิกนอกพื้นที่ |
| 2 | `toggleThemeMode()` | `main.js` | สลับโหมดสว่างและโหมดกลางคืน (Light/Dark Mode) บันทึกค่าลง `localStorage` และปรับปรุงไอคอนดวงจันทร์/ดวงอาทิตย์โดยอัตโนมัติ |
| 3 | `filterAndSearchPlaces()` | `filter.js` | ระบบค้นหาข้อความแบบพิมพ์สด (Live Search) ควบคู่กับปุ่มตัวกรองหมวดหมู่ชุมชน การเรียงลำดับ และอัปเดตจำนวนผลลัพธ์แบบไดนามิก |
| 4 | `validateContactForm()` | `contact.js` | ตรวจสอบข้อมูลในฟอร์มติดต่อแบบเรียลไทม์ (ชื่อ, รูปแบบอีเมล Regex, รูปแบบเบอร์โทรไทย 9-10 หลัก, ชุมชนที่สนใจ, ข้อความ) พร้อมแสดงข้อความเตือนรายช่องและเปิด Modal ยืนยันข้อมูล |

## 5. การเชื่อมต่อ API (Open-Meteo Weather API)

- **Endpoint**: `https://api.open-meteo.com/v1/forecast?latitude=14.9951&longitude=103.1029&current=temperature_2m,relative_humidity_2m,weather_code,wind_speed_10m&daily=weather_code,temperature_2m_max,temperature_2m_min&timezone=Asia%2FBangkok`
- **จุดเด่น**: ไม่ต้องใช้ API Key, รองรับพิกัด จ.บุรีรัมย์ อย่างแม่นยำ
- **ฟีเจอร์**:
  1. **Loading State**: แสดง Skeleton Shimmer Animation ระหว่างรอการตอบกลับจากเครือข่าย
  2. **Success State**: แสดงอุณหภูมิ (°C), สภาพอากาศภาษาไทยพร้อมไอคอน, ความชื้น, ความเร็วลม, คำแนะนำการท่องเที่ยวเฉพาะวัน, และพยากรณ์ล่วงหน้า 3 วัน
  3. **Error Handling**: ดักจับกรณี Network Failure หรือเซิร์ฟเวอร์ขัดข้อง แสดงกล่องเตือนสีแดงสุภาพ และมีปุ่ม **"ลองใหม่อีกครั้ง (Retry)"** ให้ผู้ใช้กดโหลดใหม่ได้ทันที

## 6. การออกแบบ UI/UX, Typography และ Responsive Design

- **Typography**: เลือกใช้คู่ฟอนต์ Google Fonts ไม่เกิน 2 ฟอนต์:
  - **Prompt**: สำหรับหัวเรื่อง หัวข้อหลัก (Headings) และปุ่มกด
  - **Sarabun**: สำหรับเนื้อหาทั่วไป (Body Text) อ่านง่าย สบายตา
- **โทนสีอัตลักษณ์บุรีรัมย์ (Buriram Cultural Palette)**:
  - สีกรมท่าศิลาบุรีรัมย์ (`#0e2a47` / `#1c4b77`): สื่อถึงความสง่างามและความน่าเชื่อถือ
  - สีดินภูเขาไฟ/ศิลาแลงพนมรุ้ง (`#c25e00` / `#b45309`): สื่อถึงอารยธรรมขอมและผ้าภูอัคนี
  - สีทองไหมมัดหมี่ (`#d97706`): สื่อถึงภูมิปัญญาการสาวไหมโบราณ
- **สถานะการโต้ตอบ (Hover / Focus State)**:
  - ลิงก์และปุ่มทั้งหมดมีเอฟเฟกต์ Transition นุ่มนวล
  - รองรับ WCAG AA ด้วยขอบโฟกัสชัดเจน (`focus-visible:outline` สีส้มอำพัน 3px)
- **Responsive Breakpoints**:
  - มือถือ (≤ 576px): เมนูแฮมเบอร์เกอร์, คอลัมน์เดี่ยว, ซ่อนปุ่มที่ไม่จำเป็น
  - แท็บเล็ต (≤ 992px): เลย์เอาต์ 2 คอลัมน์, ปรับขนาดกริดการ์ด
  - เดสก์ท็อป (> 992px): เมนูบาร์แนวนอนเต็มรูปแบบ, กริด 3 คอลัมน์, เลย์เอาต์กว้างสูงสุด 1280px

## 7. SEO เบื้องต้น (SEO & Accessibility)

- ทุกหน้ามี `<title>` และ `<meta name="description">` ที่เป็นเอกลักษณ์ ไม่ซ้ำซ้อนกัน
- มี `<h1>` เพียงหนึ่งเดียวต่อหน้า และโครงสร้างลำดับชั้นของ Heading ถูกต้อง (`h1` -> `h2` -> `h3`)
- รูปภาพทุกรูปมีแอตทริบิวต์ `alt` อธิบายเนื้อหาภาพ และชื่อไฟล์สื่อความหมาย
- มี Open Graph Meta Tags (`og:title`, `og:description`, `og:image`, `og:url`, `og:type`) สำหรับการแชร์ลงโซเชียลมีเดีย

## 8. ตารางบันทึกผลการทดสอบและแก้ไขข้อผิดพลาด (Testing & Bug Fixes Matrix)

ตารางบันทึกผลการทดสอบด้วย Chrome DevTools (Device Toolbar, Console), Lighthouse และ W3C Validator:

| ลำดับ | รายการทดสอบ / เครื่องมือ | ปัญหาที่พบ (Problem) | สาเหตุ (Root Cause) | วิธีแก้ไข (Solution) | ผลลัพธ์หลังแก้ไข |
| :---: | :--- | :--- | :--- | :--- | :---: |
| 1 | **Chrome DevTools Device Toolbar**<br>(ทดสอบจอขนาดเล็ก iPhone SE 375px) | เมนูนำทางและหัวข้อหลักในหน้าแรกเกิดการล้นแนวนอน (Horizontal Scrollbar) ทำให้หน้าเว็บเลื่อนซ้ายขวาได้ | คลาสบางตัวใช้ `whitespace-nowrap` และไม่ได้กำหนด `overflow-x: hidden` ในแท็ก `body` | ลบ `whitespace-nowrap` ในส่วนหัวเรื่อง ใช้ `break-words` และเพิ่ม `overflow-x: hidden` ที่ระดับ `body` ใน `custom.css` | ผ่าน 100% หน้าเว็บไม่เลื่อนในแนวนอนบนทุกขนาดหน้าจอ |
| 2 | **Console & Network Throttling**<br>(ทดสอบ Open-Meteo API เมื่อ Offline / Slow 3G) | หากผู้ใช้ตัดการเชื่อมต่ออินเทอร์เน็ต กล่องสภาพอากาศจะแสดงผลว่างเปล่าและเกิด Uncaught Error ใน Console | ฟังก์ชัน `fetch()` ล้มเหลวโดยไม่มี Error Boundary และไม่มีการแสดงข้อความแจ้งเตือนต่อผู้ใช้ในหน้าเว็บ | เพิ่มบล็อก `try...catch` ครอบการเรียก API ใน `weather-api.js` สร้างกล่องแจ้งเตือน UI สีแดงที่เป็นมิตร พร้อมปุ่ม "ลองใหม่อีกครั้ง (Retry)" | ผ่าน 100% มีข้อความแจ้งเตือนชัดเจน และสามารถกด Retry เพื่อโหลดใหม่ได้ทันที |
| 3 | **Client-side Form Validation**<br>(ทดสอบกรอกเบอร์โทรและอีเมลใน `contact.html`) | ผู้ใช้สามารถกรอกตัวเลขไม่ครบ 10 หลัก หรือใช้อีเมลที่ไม่มีโดเมน เช่น `user@domain` แล้วฟอร์มยอมให้กดส่ง | แอตทริบิวต์ HTML5 `type="email"` มาตรฐานของเบราว์เซอร์ตรวจจับโดเมนไม่เข้มงวด และ `type="tel"` ไม่ได้ตรวจสอบความยาวของเบอร์โทรศัพท์ไทย | เขียน Regex ตรวจสอบเฉพาะเจาะจงใน `contact.js`: อีเมลต้องมี TLD อย่างน้อย 2 ตัวอักษร (`\.[a-zA-Z]{{2,}}`) และเบอร์โทรต้องเป็นเลข 9-10 หลักขึ้นต้นด้วย 0 (`^0[0-9]{{8,9}}$`) พร้อมผูก Event `blur` และ `input` แจ้งเตือนทันที | ผ่าน 100% ระบบแจ้งเตือนข้อผิดพลาดตรงจุดและแม่นยำ |
| 4 | **Lighthouse & W3C HTML Validator**<br>(ทดสอบความถูกต้องและ Accessibility) | ตรวจพบค่า Contrast Ratio ต่ำในส่วนปุ่มสลับ Dark Mode และขาดป้ายกำกับกำกับเสียงสำหรับ Screen Reader | ปุ่มสลับธีมมีเพียงไอคอน Font Awesome ขาดข้อความบรรยายหรือแอตทริบิวต์ `aria-label` | เพิ่ม `aria-label="สลับโหมดสว่างและโหมดกลางคืน"` และเพิ่ม `<div id="a11y-announcer" class="sr-only" aria-live="polite">` เพื่อแจ้งการสลับธีมแก่ผู้พิการทางสายตา | ผ่านเกณฑ์ Accessibility และโครงสร้าง W3C ถูกต้องสมบูรณ์ |

## 9. วิธีการเปิดใช้งานเว็บไซต์ในเครื่อง (How to Run Locally)

เนื่องจากเป็นเว็บไซต์ที่ใช้เทคโนโลยี HTML5, CSS3, JavaScript (Vanilla ES6) และ CDN จึงสามารถเปิดไฟล์ได้โดยตรง หรือรันผ่าน Local HTTP Server ได้อย่างสะดวก:

### วิธีที่ 1: รันด้วย Python HTTP Server (แนะนำ)
เปิด Terminal / PowerShell ในโฟลเดอร์โครงการ:
```bash
python -m http.server 8000
```
จากนั้นเปิดเบราว์เซอร์ไปที่: `http://localhost:8000`

### วิธีที่ 2: รันด้วย Node.js (npx serve)
```bash
npx serve .
```

### วิธีที่ 3: เปิดไฟล์โดยตรง
ดับเบิลคลิกไฟล์ `index.html` เพื่อเปิดใช้งานบน Google Chrome, Microsoft Edge หรือ Safari ได้ทันที
